## Requirement 4 — mitigation: force the `submit_final_answer` tool call

Top failure mode by count is `MISSING_STEP` (the agent finishes with a plain-text JSON reply instead of calling `submit_final_answer`), not the injection-driven `SKIPPED_VERIFICATION` above — that one only ever fires on the purpose-built trap ticket. Requirement 4 asks for the mitigation to target the actual top mode, so that's what changed, and only that:

`agent.py`'s loop no longer accepts a plain-text final reply on the first attempt. The first time the model skips the tool call, the reply is rejected, a corrective message is appended, and the very next completion call has `tool_choice` forced to `submit_final_answer` — one extra lap, spent only on runs that actually need it. Nothing else changed: same system prompt, same three tool schemas, same model, same budgets. (The `SKIPPED_VERIFICATION`-closing guard demonstrated above is a second, independent change kept OUT of this comparison — see Common Mistake #2 — and is exercised separately in the bonus, `injection_test.py`.)

Top failure mode (10 + trap, baseline): **MISSING_STEP** — 11 -> 11 after the mitigation.

Price paid, measured on `TCK-01` (the case whose mode actually flipped):

- Iterations: 4 -> 2 (-2)
- Total tokens: 4565 -> 990 (-3575)
- Cost: $0.00050 -> $0.00011 (-0.00039)
- Latency: 619.0s -> 422.0s (-197.0s)

On the 0 case(s) that already called the tool correctly, the guard never fires, so the average cost delta there is $+0.00000 — the mitigation only costs anything on the runs it was built to catch.
